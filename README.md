# Resona

让每一份热爱，产生共鸣。

Resona 是一个自托管音乐库：Go 服务端负责本地音乐的识别、元数据刮削、复制整理和播放 API；SwiftUI 客户端负责 iPhone 和 macOS，Flutter 客户端支持 Android 手机、Android 平板与 Windows 上的在线及离线聆听。iPhone 客户端采用竖屏布局，底部导航上方独立显示播放控制栏。

## 已实现

- 首次访问 Web 设置管理员密码，之后通过用户名和密码登录。部署无需设置密码，也没有默认密码。
- MP3、FLAC、M4A、AAC、OGG、Opus、WAV、AIFF、ALAC、WMA 文件识别，读取标签、时长、码率和采样率。
- 优先使用本地标签；支持 MusicBrainz、QQ、网易云、酷狗和 iTunes 元数据，按标题、艺术家、已知专辑和时长匹配后补充缺失字段，优先采用时长一致的结果。优先提取内嵌或目录封面，再尝试 Cover Art Archive。
- 按 `专辑艺术家 / 专辑 / 歌曲名-歌手.格式` 复制入库；SHA-256 去重，完成入库、索引保存及校验后清理导入来源，失败时保留以便重试。识别出同一音乐库已有同名同歌手歌曲时跳过整理，专辑或音频格式不同也不重复入库。重新刮削和识别更正均按新标签迁移目录，同名 LRC 随之迁移。
- 手动扫描、定时扫描、重新刮削、独立任务详情、逐文件明细、提示处理、音乐搜索、专辑、艺术家、收藏。任务记录单行显示，支持勾选批量删除和全部删除，运行中任务始终保留，删除记录不影响音频或曲库。
- 歌曲识别更正：选择来源搜索候选及发行版本，核对后保存，或直接编辑标签；人工更正在后续扫描和刮削中保留。
- 歌词刮削：支持 LRCLIB、QQ、网易云、酷狗与自动回退，按歌曲身份与时长匹配；支持预览和明确替换，获取失败保留已有歌词。
- 同名 LRC 和文件标签内嵌歌词读取；旧索引首次读取时补充识别，无需重新导入。同步歌词高亮，纯文本歌词直接展示。
- 音乐库管理条目以徽标区分标签内有无歌词，外置 LRC 与在线缓存不误报为内嵌歌词。歌词预览中可将现有或刮削歌词写入 MP3、FLAC、M4A、OGG、Opus 标签；不重新编码音频，保留其他标签及封面，已有标签歌词需明确勾选覆盖。
- 服务端文件管理支持任意可访问路径、目录浏览、复制、剪切、粘贴、移动、重命名和删除，同步更新曲库索引。系统日志位于设置下方，提供等级、类别、内容筛选和自动刷新。
- 同源 Web 音频播放、受保护的 HTTP Range 流；播放栏海报悬停显示展开按钮，点击进入工作区唱片与歌词视图，支持点击同步歌词跳转，收起返回原页面。
- iOS 17+ 原生客户端：音乐库、搜索、专辑、收藏、播放队列、随机 / 循环、进度拖动、沉浸播放页、同步歌词、后台音频和带海报的锁屏控制；其他 App 音频中断时同步暂停状态。
- macOS 14+ 原生客户端：提供侧边栏、歌曲列表、底部播放器、播放队列与唱片歌词布局；页面标题单行放大，设置卡片左对齐并填满内容区，橙色音乐库切换控件与导航对齐。播放栏默认显示当前及下一句同步歌词，鼠标悬停或键盘聚焦时显示歌曲信息与右侧播放控件，暂停时控件保持可见；顶部进度条支持点击、拖动和键盘调节。支持 Apple Silicon 和 Intel。
- 独立 115 网盘管理页面：扫码授权、目录同步、STRM 生成、后台标签 / 封面 / 歌词预探测和失败重试；三端区分本地音乐库与网盘音乐库，网盘音频使用 302 直连播放。
- 内置音乐保存机器人和 Telegram 本地 API 插件：卡片配置、用户白名单、音频 / 歌词 / 封面接收、自动入库、本地 API 代理、状态、重启及缓存清理。
- iOS / macOS 直接进入音乐界面，服务器登录位于设置；下载音频、海报与歌词后可在未登录、登录过期和服务器断连时离线播放。
- 三端播放列表与统一播放模式按钮：顺序 / 列表循环 / 单曲循环 / 随机循环；全部音乐支持全部播放、随机播放、选择歌曲与加入播放列表，批量操作覆盖全部匹配结果。
- GitHub Actions 构建 Android、Windows、iOS、macOS 客户端，以及 Linux amd64 / arm64 服务端和 Docker 镜像；安装包、离线镜像包及 SHA-256 通过 GitHub Release 分发，多架构镜像发布至 GHCR。

## Docker 部署

安装 Docker Engine 与 Compose，进入项目目录：

```sh
mkdir -p music/inbox music/library
# 容器以 UID/GID 10001 运行；音乐库需要可写，导入目录需要可读。
sudo chown -R 10001:10001 music/library
docker compose pull
docker compose up -d
```

Compose 默认使用公开的 `ghcr.io/siryle/resona:latest`，自动选择 Linux amd64 / arm64 架构。可通过 `RESONA_IMAGE=ghcr.io/siryle/resona:v<版本>-<构建号>` 固定版本，或使用 Release 中 `images.txt` 记录的镜像摘要。源码构建可执行 `docker compose up -d --build`。

离线部署时，从 GitHub Release 下载对应架构的 `Resona-Docker-<版本>-<构建号>-linux-<架构>.tar.gz` 和 `.sha256` 文件，先执行 `sha256sum -c <校验文件>`，再运行 `docker load --input <镜像包>`。将 `RESONA_IMAGE` 设为导入的 `ghcr.io/siryle/resona:v<版本>-<构建号>-<架构>` 后启动 Compose。

打开 `http://服务器地址:8080`，首次访问会显示管理员密码设置页面。默认用户名为 `admin`，密码至少 8 个字符；确认后自动登录。**不需要在 Compose 或环境变量里设置密码。**

将音频文件放入 `music/inbox`，进入「任务 → 整理与刮削」点击「整理入库」。导入目录须允许容器 UID/GID 10001 写入和删除，整理后的文件写入 `music/library`。入库、索引保存及校验成功后删除导入音频与已迁移的同名 LRC；失败或存在未处理警告时保留来源以便重试。同名同歌手但内容不同的重复项仍跳过并保留。已有的 `music/library` 文件也会被扫描入库，保持其现有路径。仅更新已有曲库的索引时，使用音乐库页的「扫描音乐库」。

可选地复制 `.env.example` 为 `.env`，修改目录、端口等配置。更换宿主机目录后仍需保证容器用户的读写权限。不要将数据目录、导入目录和音乐库配置为彼此嵌套的路径。

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `ADMIN_USER` | `admin` | 首次初始化时的管理员用户名，初始化后以持久化账号为准 |
| `RESONA_PORT` | `8080` | Compose 暴露端口 |
| `RESONA_IMAGE` | `ghcr.io/siryle/resona:latest` | GHCR 镜像、固定版本或摘要，也可指定离线导入的架构镜像 |
| `MUSIC_INBOX` | `./music/inbox` | 宿主机导入目录 |
| `MUSIC_LIBRARY` | `./music/library` | 宿主机音乐库目录 |
| `COOKIE_SECURE` | `false` | HTTPS 反向代理部署时设为 `true` |
| `SCRAPE_ENABLED` | `true` | 是否启用在线元数据和在线封面 |
| `SCAN_INTERVAL` | `15m` | 兼容旧配置：`0` 表示仅手动，正值迁移为每天 `03:00`；网页保存的执行计划优先 |
| `TZ` | `Asia/Shanghai` | 容器时区 |

直接运行二进制时还可设置 `LISTEN_ADDR`、`DATA_PATH`、`INBOX_PATH`、`LIBRARY_PATH`。服务端会检查 FFmpeg / FFprobe 是否可用。

服务生成到音乐库的目录、音频和 LRC，以及插件收件目录中的目录和文件均显式设置为 `0777`，不受进程 umask 收紧。文件管理复制或移动到这两个目录时也应用该权限。导入来源仅在成功入库并校验后删除。

管理员凭据保存在数据卷 `/data/admin.json`，内容为随机盐和 PBKDF2-SHA256 哈希，权限 `0600`；音乐目录索引、歌词缓存、任务及明细、115 文件与探测队列、系统及插件配置保存在 `/data/library.sqlite`，封面缓存在 `/data/artwork`。数据库及其 WAL / SHM 文件权限为 `0600`。会话有效期 7 天，令牌摘要与到期时间持久化于权限 `0600` 的 `/data/sessions.json`，服务重启后继续有效，退出登录也会持久撤销。网页右上角提供「退出登录」文字按钮。

升级首次启动时自动将旧 `/data/library.json` 事务化导入 SQLite；成功后将原文件改名为 `library.json.migrated`，作为迁移时的私有快照。收藏、人工更正、历史内容 ID、歌词、配置和探测队列均保留；未完成的整理任务标为已中断。旧 JSON 损坏时拒绝导入，数据库损坏或版本不兼容时拒绝启动，不会自动用旧 JSON 覆盖数据库。迁移快照不包含升级后的新增数据，回退旧版前应停服并单独备份当前数据。

备份时先停止服务，再保存整个数据卷和音乐库；运行中的 SQLite 使用 WAL，不能只复制 `library.sqlite`，需要在线备份时应使用 SQLite 一致性备份工具。数据库放在服务器本地持久卷，不要放到 SMB / NFS 等网络文件系统；单个数据卷由一个 Resona 实例使用。不要在升级时删除数据卷，避免丢失账号和收藏。

「全部音乐」点击条目直接播放；上方可全部播放、随机播放或加入播放列表，也可先选择部分歌曲。未选择时操作包含所有匹配结果，而非仅已加载条目。加入队列会去重并保留当前播放和暂停状态；空队列会准备第一首，等待手动播放。播放栏可查看和切换队列歌曲，并切换顺序播放、列表循环与单曲循环，循环选择在本浏览器保留。

「音乐库管理 → 音乐库」点击条目打开歌曲详情，详情中可播放。在此页面浏览、搜索和加载全部入库歌曲，使用条目上的「识别更正」搜索候选并核对标签，也可直接手动修改。保存更正后立即按新专辑艺术家、专辑及歌曲名迁移到对应目录，音频内容保持不变。同库已有同名同歌手歌曲时跳过整理并提示冲突。已有曲库文件更名时，先发布新索引，再清理旧名称；导入目录中的来源始终保留。

音乐库页的「扫描音乐库」只遍历当前音源的本地文件：本地音乐库扫描音乐目录，网盘音乐库扫描已生成的 STRM；只更新索引，不读取导入或插件收件目录，不生成 STRM、不执行在线刮削、不写入音频标签。任务页的「整理入库」保留原有整理与刮削流程。

「任务 → 整理与刮削」点击任务进入详情页，集中查看歌曲时长、提示条目和文件明细。关联到入库歌曲的提示和明细均提供「识别更正」「刮削歌词」。未入库的失败文件或没有关联信息的旧任务提供音乐库入口，避免错误修改其他同名歌曲。已结束的任务可删除记录；这不会删除音频、歌词或音乐库索引，运行中的任务需等待结束。

「设置 → 系统设置」中的「定时整理与刮削」位于「刮削源与歌词源」下方，支持仅手动或每天指定几点几分执行。时间采用页面显示的服务端时区；保存立即生效并在重启后保留，覆盖 `SCAN_INTERVAL` 默认值。旧间隔计划迁移为每天执行，沿用保存的每日时间，未指定时为 `03:00`；原来关闭的计划保持手动。运行中的任务不会重叠启动。「任务 → 整理与刮削」中「整理入库」位于「重新刮削已有音乐」左侧。任务详情按任务单独加载，网络失败显示原因与重试按钮；历史列表不再一次传输全部文件明细。

点击明细上的「刮削歌词」可预览和获取歌词，有歌词时默认拒绝覆盖，需勾选替换。读取顺序为保存的在线版本、同名 LRC、文件标签内嵌歌词；替换不会改写原始 LRC 或音频标签。修改歌曲身份后，旧的在线歌词缓存会清除。

列表的「标签有歌词 / 标签无歌词」仅检查音频内嵌标签，外置 LRC 和在线歌词缓存不计入该徽标。 旁边独立显示「有 LRC 歌词 / 无 LRC 歌词」：只检查同目录可读取、非空且不超过 1 MiB 的 `.lrc` 文件；支持本地音频和网盘 STRM，不把在线缓存或内嵌歌词算作 LRC。列表只检查当前分页，不访问 115 或探测音频；文件新增或删除后刷新列表即可更新徽标。歌词弹窗与播放页分别标明「音频内嵌标签」「外置 LRC」或「STRM 同目录 LRC」及在线来源；因此可以同时显示「已有歌词」与「标签无歌词」。网盘歌曲可读取歌词，但不能通过 STRM 将歌词写回 115 音频文件。

在「设置」中保存默认刮削源、歌词源，也可每次操作单独切换。元数据来源包括 QQ、网易云、酷狗、MusicBrainz、iTunes、咪咕、酷我与智能标签源。默认刮削源为「自动」时，可用上移、下移调整顺序，并取消勾选以禁用单个来源；至少保留一个普通来源。扫描按优先级尝试启用项，同一来源内优先选择最接近文件时长的可信版本；允许约 1 秒的时长取整差异。如高优先级来源仅有 1–5 秒偏差的版本，会继续寻找其他来源的时长一致结果，全部来源均无更一致版本时才回退到偏差最小的可信结果。指定具体来源时只使用该来源。候选搜索也按歌曲身份与时长排序，供人工核对。人工更正继续保留。

智能标签源综合已启用的普通来源，按标题、艺术家、专辑与时长匹配评分排序，保留候选的实际来源；无需服务凭据。为避免重复请求，初始自动队列中默认禁用智能标签源，可按需开启或单独选用。咪咕与酷我本次提供元数据搜索，不提供歌词接口。默认歌词源为「自动」时，按独立的歌词优先级尝试已启用项，可排序和逐个禁用，至少启用一个歌词源；初始顺序为 LRCLIB、QQ、网易云、酷狗。指定具体歌词源时只使用该来源。扫描会为标签没有歌词的曲目写入已有缓存或本地 LRC；开启 `SCRAPE_ENABLED` 时还会按默认歌词源联网补全，已有标签歌词不会被覆盖。支持 MP3、FLAC、M4A、OGG、Opus；文件名保持不变，仅更新内容哈希和对应索引，音频不重新编码，导入原件不改写。手动候选搜索和歌词获取不受 `SCRAPE_ENABLED` 影响。需要服务端能够访问所选来源；覆盖范围及可用性取决于上游服务。

初始设置入口仅在凭据文件不存在时开放，一旦设置即拒绝再次初始化。请在把服务器开放给其他访问者之前完成首次设置。远程访问建议使用 HTTPS。

忘记密码时，先停止服务并备份数据卷，再由拥有宿主机权限的管理员移走 `/data/admin.json`，重启后重新设置；这不会删除音乐索引。不要通过删除整个数据卷重置密码。

## 115 网盘音乐库

Web 的「设置 → 115 网盘」管理账号、目录和快速生成 STRM，「任务」包含「整理与刮削」和「STRM 预探测」标签页，分别查看整理记录和网盘探测队列；iOS / macOS 在音乐界面切换「本地音乐库」和「网盘音乐库」。未指定库的旧 API 仍返回聚合结果，三端默认显示本地库。

115 网盘卡片显示真实账号头像、会员与容量，提供「刷新资料」；资料暂不可用时显示占位，不影响已有登录与任务。桌面设置双栏、手机单栏；「快速生成 STRM」与「同步同目录 LRC 歌词」开关均在同一卡片内。歌词开关保存后也用于定时生成；预探测仍在任务页独立启动。

网页切换到网盘音乐库后，同样提供「扫描音乐库」按钮：后台遍历本地 STRM 目录，按已保存的 115 文件身份重新建立索引、更新移动后的路径并清理已删除曲目，完成后刷新网盘曲库。扫描不访问 115，不生成 STRM，不下载歌词，也不启动预探测；115 未登录或音源停用时也可扫描。保留收藏、标签及人工更正；无法关联到已保存身份的外部 STRM 会跳过。本地整理任务不影响这个入口，115 生成、探测或文件操作期间需等待任务完成。扫描结果和文件明细显示在任务记录中。

1. 点击「扫码登录」，选择支付宝（默认）、微信、安卓、iOS、网页、PAD 或 TV，再使用 115 客户端扫码并确认。参照 DDSRem-Dev/MoviePilot-Plugins 的 Cookie 扫码流程，无需申请或填写应用 ID，也不使用 Open API。切换方式会自动更换二维码；取消或过期后点击「刷新二维码」重试。所选方式决定登录设备，可能使同类设备的旧会话失效。
2. 「Resona 主服务地址」默认使用当前访问地址，STRM 播放入口与管理页面共用主服务端口，无需额外开放或映射端口。例如管理页面为 `http://10.10.10.10:35280`，STRM 内容为 `http://10.10.10.10:35280/api/v1/tracks/<歌曲ID>/stream`。反向代理请填写客户端可访问的完整地址，有路径前缀时须包含前缀。点击「选择目录」打开目录选择弹窗，通过面包屑和文件夹列表进入目标目录后确认；输入框显示完整路径，目录 ID 仅供后台使用。旧设置只有 ID 时会自动补全路径。启用音源并保存。修改主服务地址后，重新执行「快速生成 STRM」更新已有文件。
3. 点击「快速生成 STRM」。服务端使用 Cookie，从 Web `/files/get_info` 获取目录信息，缺少 PickCode 时通过 `/files/file` 补取，再分页读取 proapi `/app/2.0/chrome/downfolders` 目录树和 Web `/files` 递归文件清单（`cur=0&type=99`，每页 5000 项），完整校验后一次更新索引并批量生成全部 STRM，随即按文件名建立基础曲目并刷新网盘音乐库，无需等待探测即可查看和播放。任务启动后立即在后台运行，离开页面不会中断；页面显示目录树、文件清单、生成数量和索引刷新阶段。目录仅准备一次，未变化的 STRM 不重写。目录树接口不可用时自动回退逐目录扫描并显示进度；账号根目录 `0` 直接逐目录扫描。单次最多 10000 个目录、100000 个文件，超过时需缩小同步范围。定时同步选择每天指定时间，或设为仅手动；旧的正分钟间隔迁移为每天 `03:00`，原先关闭的计划保持手动。手动和定时生成均不会自动启动预探测。
4. 可在快速生成区域勾选「下载歌词」。生成并刷新曲库后，服务端将同一远端目录中与歌曲同名的 `.lrc` 校验并同步到 STRM 同目录，权限 `0777`；未探测歌曲也可读取。未变化的歌词不重复下载，下载失败保留已有副本并记录日志；取消勾选不删除已同步歌词。删除 STRM 后重新生成时会补齐缺失歌词；115 持续返回 405/429 时暂停歌词下载，显示剩余数量，已生成 STRM 和曲库索引均保留，稍后重新生成可重试。
5. 在「任务 → STRM 预探测」点击「开始预探测」，将待探测歌曲按远端相对路径排序加入持久化 FIFO 队列。服务端只有一个探测工作线程，完成当前歌曲的标签、时长、封面及索引更新后，才探测下一首，已同步 LRC 随 STRM 整理迁移。普通单首失败不阻塞后续歌曲；115 持续返回 405/429 时暂停并保留队列，稍后点击「开始预探测」继续。失败项可单独或批量重新入队，同一首不会重复排队。已准备歌曲可单独重新探测。远端标签与封面探测每首总计最多 2 分钟，超时记录为失败后继续下一首。
6. 两项任务都有独立的「终止」按钮。终止生成会取消目录请求与后续写入，保留已生成文件和现有曲目；再次生成会复用未变化文件。终止预探测会中断当前远端请求并保留未完成队列，手动暂停状态在重启后仍然有效，点击「开始预探测」继续。单次生成任务上限 30 分钟，超过时停止并提示缩小目录范围。

STRM 生成完成后歌曲即进入客户端音乐库，未探测歌曲先显示文件名推导的标题和歌手，时长与封面等待预探测补全；已有曲目保留收藏和人工更正。列表、封面和歌词读取不会触发远端音频探测。后台进度、失败原因和重复歌曲的「已跳过」状态可在管理页面查看。同名同歌手只在同一个库内去重，本地库与网盘库互不阻挡。客户端封面仍通过认证后的歌曲 `artwork` 路径读取，服务端 JPEG 缓存在 `/data/artwork/<歌曲ID>.jpg`。

下载地址请求优先使用 Android Cookie 接口 `/android/2.0/ufile/download`，参照 MoviePilot-Plugins，仅加密发送 `pick_code`，不添加 `user_id` 或时间戳；受限或返回需要 Cookie 的地址时尝试 Chrome 接口，并复用成功的接口。保留播放器 User-Agent，只读请求有限重试并遵守冷却，持续 405/429 不会循环请求整库。

「下载接口连接」默认 **HTTPS**。若 HTTPS 持续返回 405，可在「设置 → 115 网盘」手动选择 **HTTP（参考项目兼容）** 并保存，与 MoviePilot-Plugins 的 Cookie 302 下载请求协议一致。**HTTP 会明文传输 115 登录 Cookie，存在被窃取和篡改风险，仅在信任的网络中自行选择启用；不会自动降级。** 该选项仅影响服务器向固定 115 下载接口获取地址，不改变扫码、目录接口、Resona 主服务端口或 CDN 地址协议。切换后清除临时直链缓存；播放可直接重试，预探测需手动继续，歌词同步需再次生成。它是协议兼容选项，不保证解除账号或 IP 风控。服务端保留限流退避，持续限制时应等待或重新扫码，而非不断重试。

播放仍通过主服务端口 302 跳转到受信任的 115 CDN，不转发登录凭据，不代理音频，也不跟随携带登录 Cookie 的接口重定向。网页播放失败时只刷新一次地址；服务端请求失败会显示具体原因并写入 STRM 日志，不再统一提示格式不支持。

生成的 STRM 位于 `/data/cloud115/strm/<专辑艺术家>/<专辑>/<歌曲ID>/<歌曲名-歌手>.strm`，探测前暂存于 `/data/cloud115/strm/tree/<账号>/<网盘相对目录>/<歌曲ID>/`，STRM 与生成目录权限为 `0777`。内容为 Resona 的 `/api/v1/tracks/<ID>/stream` 地址，需要有效的 Resona 登录；不包含 115 临时下载地址、Token 或 Cookie，也不是匿名通用播放器直链。识别更正只迁移本地 STRM 和对应 LRC，不移动或写回 115 音频。115 文件身份、SHA-1、准备状态和登录 Cookie 保存在权限为 `0600` 的 `/data/library.sqlite`；Cookie 不返回客户端，请妥善备份数据卷。

通过文件管理删除 STRM 或其目录时，同步移除网盘音乐库索引、网盘条目和预探测队列，进行中的探测不会重新发布已删除的歌曲；移动或重命名到网盘 STRM 根目录内部时保留索引。直接从磁盘删除的 STRM 会在服务启动、打开 115 管理页或每分钟检查时清理，读取权限等其他错误保留索引。再次手动或定时运行「快速生成 STRM」会按远端文件重新生成已删除的歌曲。

播放时服务端鉴权，通过 Cookie 与 RSA 加密的应用端下载接口按客户端 User-Agent 获取或复用短时下载地址，返回 `302`，音频直接从 115 CDN 到客户端；不使用有 200 MB 限制的 Web GET 下载接口。如果上游返回需要额外 Cookie 的 CDN 地址，会拒绝播放并提示重新登录，不泄露 Cookie 或偷偷代理音频。客户端须能访问 115 CDN；播放失败会尝试刷新地址一次。网盘歌曲 ID 是账号与文件 ID 的稳定摘要，与音频内容摘要独立；原生客户端下载后按 115 SHA-1 校验，本地音乐继续按 SHA-256 校验。云端歌曲不支持写入音频歌词标签。

115 下载地址和网页播放安全策略共用受信任域名列表：`115.com`、`115cdn.com`、`115cdn.net`、`anxia.com` 及其子域，兼容上游返回的 HTTP / HTTPS 和对应默认端口，标签和封面预探测也支持这两种协议，不改写带签名的原始地址；其他域名、非默认端口和含用户信息的地址仍拒绝。拒绝信息只补充协议与主机，不输出签名查询参数。升级后，因旧域名校验失败的歌曲可点击「重试失败项」重新进入串行预探测队列，无需重新生成 STRM 或扫码登录。

队列保存在 `/data/library.sqlite`，重启后继续已入队而未完成且未被手动暂停的预探测，未入队的待探测歌曲不会自动开始。生成与预探测有各自的运行状态；探测期间仍可生成 STRM，若当前音频被同步修改则丢弃旧探测结果并按新版本重探测，已移除项跳过。同步增量处理新增或变更内容。只有完整遍历成功才标记远端缺失，临时网络或登录失败保留已有索引；分页不完整、重复条目、目录树异常或 HTTP 405 也不会覆盖索引或标记歌曲缺失。115 读取请求遇到 HTTP 405 / 429 时最多重试 3 次，按 `Retry-After`（最长 120 秒）或 1 / 2 / 4 秒退避；持续失败时日志包含具体接口路径，不记录查询参数或 Cookie。115 API 请求使用直连，不经过进程的 `HTTP_PROXY` / `HTTPS_PROXY`。断开账号或 Cookie 失效时保留缓存和收藏，并将云端音频标记为不可用，需重新扫码登录。旧版 Open API 令牌不会转换成 Cookie：升级后需重新扫码，已生成 STRM、封面、歌词及收藏保持不变。重新登录、设置修改和识别更正会在后台任务结束后开放，避免路径或身份冲突。

## 文件管理与系统日志

这两个页面仅提供在服务端 Web，不添加到 iOS / macOS 客户端。

「文件管理」分为「本地管理」「115网盘」标签页，115 未登录时隐藏网盘标签。两种存储分别保留浏览位置，切换时清空剪贴板，避免跨存储误操作。

「本地管理」支持从 `/` 浏览服务器进程能够访问的文件系统，输入绝对路径、上级目录和目录链接均可跳转。音乐库、导入目录、插件收件目录与 STRM 目录为快捷入口。支持选择、复制 / 剪切 / 粘贴、移动、重命名及确认删除；最多单次选择 100 项，递归复制每次最多 10000 个条目。重名目标保留原文件并显示错误；批量操作失败时显示已完成数量。移动、改名与删除同步更新曲库索引，复制后运行扫描入库；扫描或写入标签期间返回忙碌提示。中断的索引修改在下次启动时恢复。Docker 中可访问范围由挂载和 UID / GID 权限决定，默认导入目录为可写，以支持入库后的来源清理。

文件管理采用统一的路径面包屑、目录统计和紧凑操作栏，文件夹、音乐与其他文件使用不同图标，支持选中行反馈及小屏布局。

「115网盘」使用已登录账号的服务器端 Cookie 浏览绝对路径，支持复制、剪切、粘贴、移动、重命名及移入回收站。目标同名时保留原文件，不允许操作根目录或将目录移入自身。操作时需等待 STRM 生成与预探测结束；远端操作完成后重新快速生成 STRM，更新网盘音乐库。

「系统日志」位于「设置」下方，记录系统运行、整理与刮削、STRM 生成、STRM 预探测、302 播放、插件状态及设置更改。生成日志包含启动、目录清单、批量进度、歌词同步与完成 / 终止 / 失败；预探测日志包含队列及逐首开始、成功、失败与终止。「302 播放」独立记录网盘歌曲的跳转、地址获取失败和歌曲不可用，包含歌曲 ID、标题、歌手、请求方式、是否强制刷新、返回状态及地址解析耗时；成功跳转仅记录 CDN 主机名，不记录完整临时地址、签名或播放器凭据。缓存命中的跳转同样记录；302 仅代表服务端发出跳转，不代表客户端已成功播放。可按 DEBUG / INFO / WARN / ERROR、类别和关键词筛选，查看等级计数，每 5 秒自动刷新，支持暂停、手动刷新和确认清空。最多在内存保留 2000 条；数据目录中的 `runtime.log` / `runtime.log.1` 按约 2 MiB 轮转，重启后恢复现存记录。密码、Token、Cookie、API Hash 和请求 URL 查询参数在记录前脱敏；文件日志权限为 `0600`。客户端搜索框固定显示，未登录或断连时可搜索已下载音乐。

## 插件

「设置」统一提供「系统设置」「插件」「115 网盘」三个标签页；原设置内容位于「系统设置」，侧栏不再单列插件和网盘入口。插件位于「设置 → 插件」。两张卡片分别提供配置、启停和重启，显示运行状态与最近保存的文件。参考版本为 MusicSaverBot 1.0.45 和 TelegramLocalApi 1.0.12，以 Go 移植，无需安装 MoviePilot 或 Python 依赖。

音乐保存机器人通过 Bot Token 长轮询接收音频、音频文档、语音、LRC / TXT 与音频缩略图。白名单填写 Telegram 用户数字 ID，每行一个，留空接受所有用户。API 地址留空使用云端，填写 `local` 使用内置本地 API，也可填写自定义 HTTP / HTTPS API 根地址。不要让其他机器人或 Webhook 同时使用该 Token。

下载先写入 `/data/plugins/musicsaverbot/inbox` 下的隐藏临时文件，校验文件大小、完成写入后再公开，随后自动发起整理，入库规则与普通扫描相同。此目录随数据卷持久化，成功入库后清理插件收件目录的来源音频和已迁移歌词。音频上限 2 GiB，歌词 1 MiB，封面 5 MiB；云端 Bot API 下载还受 Telegram 自身限制。重复内容复用已有文件，同名不同内容追加摘要，保留来源与原始 Telegram 消息。与歌曲名和歌手匹配的晚到歌词关联到唯一已入库条目；匹配不唯一时保留在收件目录，供手动处理。

本地 API 使用 Telegram 的 API ID / Hash，通过 Go MTProto 直接接收文件，默认只监听 `127.0.0.1:8081`，无需映射额外端口。支持 HTTP / SOCKS5 代理、可选状态日志、按小时定期或手动清理超过 24 小时的下载缓存；清理保留登录会话、待处理消息和音乐收件目录。切换内置服务无需注销云端会话。请停用使用相同 Token 的其他音乐接收服务，避免重复接收。

插件与本地服务均编译进 Go 服务端，所需协议源码已固定版本并纳入 `vendor/`。Docker 构建不再从 GitHub 拉取参考项目，也不需要 C++、CMake、TDLib 或额外服务进程；`GOPROXY=off GOSUMDB=off go build -mod=vendor` 可独立编译服务端。Docker 仍需预先具备基础镜像和 Alpine 运行包，本地 API 也可直接使用 Linux 服务端压缩包。内置服务仅实现 Resona 需要的 `getUpdates`、`getFile`、`sendMessage`，不作为通用 Telegram Bot API 替代品。

凭据保存在权限为 `0600` 的索引中，查询接口仅返回是否已配置；Token、API Hash、代理密码输入留空保留已有值。会话、待处理消息与文件引用也按私有文件存储。服务日志默认关闭，开启后仅记录连接与缓存状态。第三方来源与许可见 [THIRD_PARTY.md](THIRD_PARTY.md)，Resona 按 GPL-3.0 许可交付。

## iOS 客户端

在 Release 附件、GitHub Actions 产物或本地构建的 `artifacts/` 目录中获取 `Resona-iOS-<版本>-<构建号>-unsigned.ipa`，通过自己的签名工具重新签名后安装。未签名 IPA 不能直接安装到普通 iPhone。

迷你播放栏提供播放 / 暂停与播放列表入口；点击歌曲区域进入全屏播放页。播放页中央点击海报切换到歌词，再点击歌词区域切回海报；底部保留上一首、播放 / 暂停、下一首、统一播放模式及播放列表。设置页提供服务器连接、音乐库刷新与播放缓存清理，整理和刮削在服务端管理。

客户端直接进入音乐界面；在「设置 → 登录服务器」输入完整服务器地址、用户名和密码。首次连接前先在服务端网页设置管理员密码。登录令牌保存在设备 Keychain，密码不落盘。局域网访问首次会请求本地网络权限。

通过歌曲右侧菜单下载到本机，在「已下载」播放或删除。下载在前台进行，完成前请保持客户端打开；音频通过 SHA-256 校验后才入库，同时尽量保存海报与歌词，缺失的附属资源不影响本地音频播放。已下载歌曲优先从本地播放，不需要有效登录或服务器在线。服务器断连时曲库回退到下载内容；登录过期及退出登录也保留下载，不中断正在播放的本地歌曲。手动删除正在播放的下载会先停止该歌曲。下载内容是下载时的快照，如需更新海报或歌词，可删除后重新下载。

两端客户端在在线歌曲实际开始播放后，串行下载完整音频到本机播放缓存，并尽量保存封面与歌词；本地库按 SHA-256、网盘库按 115 SHA-1 校验完成后才使用，下次播放优先读本机。首次播放仍即时串流，缓存下载未完成前继续使用服务器。缓存按服务器地址与用户名隔离，重新登录同一账号可复用，系统可能回收 Caches 中的数据。「设置 → 播放缓存 → 清理缓存」会取消并等待缓存任务后删除播放缓存，保留用户手动下载的歌曲。缓存占用显示所有账号的播放缓存总量；客户端需保持运行以完成缓存，不保证被系统挂起后继续下载。

音频按原始格式传输，不进行转码。浏览器和 Apple 客户端可播放的格式由各自的原生解码能力决定；OGG / Opus / WMA 等格式不能保证在 iOS 上播放。常用客户端音源建议使用 MP3、AAC / M4A 或 FLAC。LRC 使用 UTF-8，和原音频同名放在导入目录，整理时一起复制。未下载歌曲在线播放时会获取服务器当前歌词，已下载歌曲使用本机快照：LRC 同步高亮，纯文本直接展示，无歌词时显示空状态。锁屏海报从本机下载或通过认证请求加载，切歌时取消旧请求；系统中断时立即更新按钮与锁屏状态，仅在系统允许且中断前正在播放时恢复。

iOS 使用音乐播放的系统路由共享策略，监听音频设备连接和路由配置变化；播放中的路由恢复直接由播放器处理，不依赖解锁或界面刷新。耳机断开时暂停，用户已暂停或正在通话中断时不因设备连接自动播放。真机验收需分别验证在线、已下载歌曲在锁屏后连接蓝牙耳机、断开、重新连接，以及暂停和通话期间连接耳机；模拟器通知测试不能验证真实蓝牙输出。

## macOS 客户端

从 Release 附件、GitHub Actions 产物或本地构建的 `artifacts/` 目录获取 `Resona-macOS-<版本>-<构建号>-universal.dmg`，打开后将 `Resona.app` 拖到「Applications」快捷方式安装。需要 macOS 14 或以上，包含 Apple Silicon 与 Intel 架构。当前使用本机临时签名（ad-hoc），未使用 Developer ID 签名或 Apple 公证；系统对网络下载的 App 可能要求在「系统设置 → 隐私与安全性」允许打开。

侧边栏包含全部音乐、专辑、艺术家、喜欢与已下载，右侧工作区提供搜索与批量播放。底部播放器支持进度、音量、上一首 / 下一首、统一播放模式和播放队列，点击海报展开唱片与同步歌词。服务器连接在设置中配置，离线使用方式与 iOS 相同。

全部音乐、专辑详情、艺术家详情、我喜欢的与已下载共用歌曲列表：保留品牌文案及行首封面，支持歌曲 / 专辑 / 歌手搜索、喜欢 / 已下载筛选，保持歌曲原有顺序。列表右上角的勾选图标进入选歌模式，可单选、全选当前结果；搜索和筛选保留隐藏的已选歌曲。底部选歌操作栏覆盖原播放栏，提供下载、喜欢、加入播放列表三个图标按钮；加入时按列表原有顺序追加并去重，不切换当前歌曲。「完成」或 `Esc` 只退出选歌并恢复播放栏。批量喜欢跳过已喜欢的歌曲，下载跳过已有下载；操作显示进度，失败后保留选择以便重试。离线时仍可选歌加入播放列表，不能修改喜欢或发起下载。

侧边导航图标居中于固定宽度列，文字左对齐，整行按钮区域均可点击。设置为主窗口内的页面，通过右上角齿轮或 `⌘,` 进入，服务器配置位于设置页顶部，侧边栏不再提供设置按钮。iOS 迷你播放器显示在标签栏上一排，不覆盖底部导航。

播放栏仅让具体按钮与进度条参与键盘焦点，鼠标移出后恢复歌词显示，上一首、播放 / 暂停、下一首始终可见；点击海报切换播放页，也可按 `Esc` 收起播放页与队列。

菜单栏左侧显示当前歌词，右侧常驻上一首、播放 / 暂停、下一首和喜欢按钮，最右侧为 Resona 标志设置入口，关闭主窗口后仍可控制播放。喜欢状态与主窗口同步，离线或未登录时不可修改。点击 Resona 图标或歌词打开播控面板，切换桌面歌词、菜单栏歌词及桌面歌词锁定，调整字号，或重新打开主窗口。桌面歌词单行显示当前一句，未同步或无歌词时显示歌曲名称；悬停显示播控与关闭按钮，拖动空白区域移动。锁定后鼠标穿透，可从菜单栏或「播放」菜单解除锁定；显示开关、锁定、字号与位置会保存。使用菜单栏的「退出」或 `⌘Q` 完全退出客户端。

主窗口「设置 → 歌词与菜单栏」集中管理桌面歌词、锁定及字号，并独立开关菜单栏歌词与播控；设置与弹出面板、应用菜单实时同步。菜单栏歌词与紧凑播控共用一个原生状态栏项目，歌词在左、播控在右，默认整组位于无线等系统图标左侧。刘海屏根据右侧安全区域预留固定宽度，短歌词不收缩、长歌词截断，避免歌词变化导致其他图标反复插入；普通屏幕歌词最多 160 点宽。歌词使用 14 点字体，播控使用 16 点符号，五个按钮统一使用 24 点点击区域，程序入口使用主标志的单色矢量图，保持原始比例并随菜单栏明暗切换前景色。按住 `⌘` 可整体拖动，后续保留系统记住的位置；升级时仅修正旧版最右侧的初始位置，不修改其他应用的设置。关闭菜单栏播控后保留 Resona 图标入口，仍可打开原有播放面板。

右键点击 Dock 中的 Resona 图标，可查看当前歌曲、歌手和专辑，播放 / 暂停、切换上一首或下一首、喜欢 / 取消喜欢，并选择顺序播放、列表循环、单曲循环或随机播放。菜单每次打开时读取播放器状态，喜欢操作与主窗口共用请求状态和离线限制；关闭主窗口后仍可操作。Dock 的「选项」「显示所有窗口」「隐藏」「退出」由系统提供。

快捷键：`⌘R` 刷新、`⇧⌘P` 播放 / 暂停、`⌘←` 上一首、`⌘→` 下一首、`⇧⌘D` 切换桌面歌词。两端共用 API、Keychain、下载校验、离线索引、歌词解析与 AVPlayer 逻辑；界面分别使用各自原生 SwiftUI 控件。

## Android / Windows 客户端

共享客户端位于 `clients/resona`，按手机、平板及桌面宽度自适应导航。支持登录凭据安全保存、本地 / 网盘曲库、搜索、专辑、艺术家、收藏、播放、同步歌词、自动播放缓存及缓存清理；Android 包含媒体通知与后台音频服务。

GitHub Actions 在对应系统构建 Android APK、Windows x64 EXE 安装包、iOS IPA 和 macOS DMG，并提供 SHA-256。Android 默认产出开发证书签名的预览 APK，正式签名可配置 Secrets；Windows 安装包暂无 Authenticode 签名，包含所需的 Visual C++ 运行库，支持原目录升级、同版本修复和阻止降级，保留登录、下载与播放状态。以前解压的 ZIP 不属于已注册安装，需要先用 EXE 安装一次。Windows 播放详情在主窗口显示，采用与 macOS 一致的唱片封面和歌词布局，保留侧栏与底部播放控制。正式产物从 GitHub Release 获取，构建期间也可在 Actions 运行记录的 Artifacts 中下载。详细环境、签名与验证说明见 [客户端文档](clients/resona/README.md)。

## 版本与发布

Git 仓库仅保存源码及必要的资源、配置和文档。`artifacts/`、`dist/`、`.build/`、`build/` 和生成的版本配置等构建文件不入库；安装包及其 SHA-256 文件通过 CI Artifacts 或 Release 附件分发。

`VERSION.json` 是唯一产品版本源。Go 编译时嵌入此文件；iOS 构建前生成不入库的 `ios/Generated/Version.xcconfig`，macOS 构建生成 App 内的版本与源码摘要；Flutter 版本、Docker 标签、产物名和 Release 标签读取同一文件。标签格式为 `v<版本>-<构建号>`。

需要交付新版本时，先按语义化版本更新版本源，并将构建号加一。纯文档修改不升级。未发布的开发构建可以替换；已发布的不同内容必须升级版本，禁止覆盖。发布重跑保留原版本与构建号，CI 校验已有附件的字节一致性。

1. 先更新 `VERSION.json`，完成源码并运行测试。
2. 提交源码与版本源，从版本源生成标签并一起推送到 Gitea：

   ```sh
   TAG="v$(python3 scripts/version.py)"
   git tag "$TAG"
   git push --atomic origin main "$TAG"
   ```

3. Gitea 将源码和标签同步到公开的 GitHub 仓库。标签推送触发 `.github/workflows/clients.yml`，GitHub Actions 分别在 Linux、Windows、macOS runner 测试并构建所有客户端、服务端和 Docker 镜像，无需提交本地构建文件。
4. 所有测试和构建成功后，CI 汇总并核对版本、Apple 源码摘要、可执行文件架构、Docker 版本及源码标签和 SHA-256，再将 amd64 / arm64 镜像与多架构清单推送至 `ghcr.io/siryle/resona`。
5. CI 创建 GitHub 草稿 Release，上传并回读核验所有安装包、服务端包、可供 `docker load` 的离线镜像包、镜像摘要与校验文件，成功后发布。已发布版本重跑会跳过构建发布；相同版本来自其他提交时拒绝发布，必须升级版本。

Gitea 只负责源码与标签镜像，不执行发布工作流。版本标签必须从 Gitea 一起同步，避免后续镜像同步删除只存在于 GitHub 的标签。手动运行 GitHub 工作流重试时必须选择与 `VERSION.json` 匹配的版本标签。未发布草稿允许替换失败构建的附件，已发布附件不允许增加或覆盖。

GitHub 工作流使用内置 `GITHUB_TOKEN`，发布任务仅申请 `contents: write` 和 `packages: write`，无需 Docker Hub 凭据。公开仓库与 GHCR 包分别管理可见性；首次发布后需确认 GHCR 包也设为公开，才能匿名拉取镜像。Android 正式签名所需的可选 Secrets 见客户端文档。
